# 贡献约定

欢迎改进解释、增加有意义的失败案例、修正版本对应关系和翻译。每次改动应回答一个具体问题，并让读者更容易复现或判断结果。

## 文件布局与职责

| 路径 | 内容 |
| --- | --- |
| `docs/zh/`、`docs/en/` | 一一对应的中英文正文 |
| `src/codex_lab/` | 机制实验、MCP 服务及真实 CLI 适配器 |
| `examples/` | Taskboard、练习、指令树与 MCP 只读数据 |
| `tests/` | 正常与失败行为验证 |
| `scripts/`、`site/assets/` | 统一入口、静态构建、可编辑 SVG 来源与交互 |
| `references/`、`reports/` | 固定来源、版本记录与验收证据 |
| `.cache/`、`dist/` | 不提交的临时文件和可重建网站 |

## 改课文

同时修改两种语言，保留相同的章节和实验覆盖。翻译可以为自然表达调整句子顺序，但不能删掉失败条件、限制或验证步骤。官方行为附近应链接到对应文档或固定 commit 的源码。

每个课程章节都应具备目标、运行步骤、预期结果、故障排查与练习。不要仅增加一段概念定义就宣称覆盖了一个主题。需要新章节时，在 `scripts/build_site.py` 的页面清单中注册，并补齐两种语言。

网站使用仓库内的小型 Markdown 渲染器，支持标题、段落、围栏代码、链接、图片、强调、平铺列表、引用与表格。它会转义原始 HTML；不支持 MDX、嵌套列表、脚注或表格单元格中的原始管道字符。请把复杂层级拆成小节，把包含管道的命令放进代码块。

## 改实验

先说明要验证的行为。例如“写入失败时原文件不变”比“调用某个函数”更适合作为测试目标。新增失败用例时，验证错误后的持久化状态与进程退出码，不能只匹配一句错误提示。

机制模型应保持边界清楚；不因使用与产品相同的函数名就把模型称为官方实现。真实集成必须使用官方 CLI 或协议，明确认证、用量、超时与输出限制。默认测试不调用模型。

```sh
python3 scripts/course.py check
python3 examples/taskboard/.agents/skills/taskboard-check/scripts/check.py
python3 scripts/draw_diagrams.py
python3 scripts/course.py build
```

## 改网站或图解

通过 Python 修改并重新生成 SVG；保留脚本与导出结果。网站改动后，至少检查中文默认页、英文同章切换、搜索、窄屏导航、复制按钮和键盘可达性。进度与主题仅保存在浏览器本地。不要添加追踪器、远程字体或未经请求的分析服务。

## 升级上游版本

先在独立变更中核实可获得的 tag 和 commit，再更新 `references/upstream.json`、源码地图、相关命令和验证记录。官方在线文档会继续变化，固定源码不等于固定官网；有差异时必须说明比较对象。不要仅替换版本号。

本仓库不复制相邻课程的资产；教学代码、文案和图解使用 MIT 许可证。引用 OpenAI 源码时保留链接与上游 Apache-2.0 归属。贡献者提交的新增内容应具备相同的可分发权限。
